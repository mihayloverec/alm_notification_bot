# ALM Notification Bot

Telegram-бот для рассылки уведомлений игрокам турниров.

- Игроки подписываются на интересующие турниры через меню бота и получают уведомления только по своим.
- Админы добавляют, редактируют, открывают/закрывают турниры и рассылают сообщения (по конкретному турниру или по всем пользователям).
- Поддерживается **markdown-форматирование** и **медиа** (одно фото/видео/документ + подпись на сообщение).

Спецификация: [docs/specs/2026-05-15-alm-notification-bot-design.md](docs/specs/2026-05-15-alm-notification-bot-design.md).

## Возможности

### Для игроков
- `/start` — регистрация в боте и главное меню.
- Просмотр списка активных турниров с описаниями.
- Подписка / отписка от любого количества турниров.
- Список своих подписок (закрытые турниры показываются с пометкой `[Закрыт]`).
- Автоматическое получение рассылок по подписанным турнирам и общих рассылок «по всем».
- 📨 **Обращения в СК / ДК** — отправка сообщения (с фото или документом и форматированием) выбранным админом получателям. Получатели обращений настраиваются администратором.

### Две роли с расширенным доступом
- **Админ** — `user_id` указан в `ADMIN_IDS` в `.env`. Полный доступ: всё ниже + управление получателями обращений и списком организаторов.
- **Организатор** — добавляется админом из бота. Может делать рассылки, управлять турнирами и видеть список игроков (read-only). Не может банить, управлять СК/ДК или назначать других организаторов.

### Для админов
- `/admin` — админ-меню (полное).
- **Добавить турнир** — пошаговый мастер (название → описание → превью → сохранить).
- **Управление турнирами** — редактировать название/описание, открывать и закрывать турнир.
- **Рассылка** с выбором аудитории:
  - 👥 Все пользователи бота
  - 📋 Подписчики конкретного турнира
- Превью сообщения и подтверждение перед отправкой.
- Отчёт после рассылки: отправлено / заблокировали бота / ошибки.
- **Игроки** — просмотр всех зарегистрированных пользователей с пагинацией и поиском, бан/разбан, ручная подписка/отписка игрока от турниров.
- Заблокировавшие бота и забанённые админом помечаются автоматически и исключаются из последующих рассылок.

## Быстрый старт

Требования: **Docker** и **Docker Compose v2** (`docker compose ...`).

```bash
# 1. Получить токен у @BotFather и узнать свой Telegram user_id (например через @userinfobot)
# 2. Скопировать .env.example в .env и заполнить значения
cp .env.example .env
# отредактируй .env (см. ниже)

# 3. Собрать и запустить
docker compose up -d --build

# 4. Посмотреть логи
docker compose logs -f bot

# 5. Открыть бота в Telegram и отправить /start
```

База данных SQLite живёт в `./data/bot.db` (volume), переживает пересборку контейнера.

## Конфигурация

Все настройки берутся из `.env`. Файл `.env.example` — шаблон:

| Переменная | Обязательная | Описание | Пример |
|---|---|---|---|
| `BOT_TOKEN` | да | Токен от [@BotFather](https://t.me/BotFather) | `123456:ABC-DEF...` |
| `ADMIN_IDS` | да | Telegram `user_id` админов через запятую, без пробелов | `123456,789012` |
| `DB_PATH` | нет | Путь к SQLite внутри контейнера | `/app/data/bot.db` |
| `LOG_LEVEL` | нет | `DEBUG`, `INFO`, `WARNING`, `ERROR` | `INFO` |

Узнать свой `user_id` можно через [@userinfobot](https://t.me/userinfobot). Несколько админов — через запятую: `ADMIN_IDS=111,222,333`.

Изменил `.env` → перезапусти контейнер: `docker compose restart bot`.

## Команды и UX

### Игрок

| Команда | Что делает |
|---|---|
| `/start` | Регистрация + главное меню |

В главном меню две кнопки:
- **📋 Турниры** — список активных турниров. Тап → карточка с описанием → кнопка «Подписаться/Отписаться».
- **✅ Мои подписки** — список твоих подписок (с пометкой `[Закрыт]` для неактивных).

### Админ

| Команда | Что делает |
|---|---|
| `/admin` | Открывает админ-меню |

Меню:
- **➕ Добавить турнир** — мастер из трёх шагов: название → описание → превью + Сохранить/Отмена.
- **📝 Управление турнирами** — список всех турниров (`🟢` активные, `🔴` закрытые). Тап → карточка с кнопками:
  - ✏️ Название
  - ✏️ Описание
  - 🔒 Закрыть / 🔓 Открыть
- **📢 Рассылка** — мастер:
  1. Выбор аудитории: `👥 Все` или конкретный турнир.
  2. Бот просит прислать сообщение для рассылки (текст, фото с подписью, видео и т.д. — всё, что Telegram отдаёт одним сообщением).
  3. Бот показывает количество получателей и просит подтвердить. На этом же шаге можно `➕ Добавить кнопку` — URL-кнопку (текст + ссылка), которая прикрепится к сообщению при отправке. Несколько кнопок — каждая в свой ряд. Кнопки можно сбросить и набрать заново.
  4. После подтверждения шлёт «Рассылка запущена», а по завершении — финальный отчёт.
- **👥 Игроки** — управление пользователями бота:
  - Пагинированный список (10 на страницу) с пометкой `🚫` для забанённых.
  - 🔍 Поиск по `@username`, имени и Telegram ID.
  - Карточка игрока показывает username, имя, ID, дату регистрации, статус и число подписок. В карточке доступны:
    - `🚫 Забанить` / `♻️ Разбанить` — soft-бан: игрок не получает рассылок и видит «Вы заблокированы администратором» при попытке взаимодействия. Подписки сохраняются. Админ не может забанить сам себя или другого админа.
    - `➕ Подписать на турнир` — выбрать активный турнир и подписать игрока вручную.
    - `📋 Подписки игрока` — список текущих подписок с возможностью снять любую из них.
- **📨 Получатели обращений** — управление тем, кому пересылаются обращения игроков:
  - Отдельные списки получателей для **СК** и **ДК**, любого размера.
  - Добавление через тот же пагинированный список игроков (никаких username/ID вручную).
  - Удаление получателя через подтверждение.
  - Если у типа нет получателей — кнопка для игроков становится «временно недоступна».
  - При отправке обращения каждому получателю приходят два сообщения: заголовок с `@username`, `id`, именем отправителя и копия самого обращения (с медиа и форматированием).
- **👨‍💼 Организаторы** — кому делегировать рассылки и работу с турнирами:
  - Список текущих организаторов (тап → подтверждение снятия).
  - Добавление двумя способами: пагинированный список игроков ИЛИ ручной ввод `@username` / `user_id` (FSM-поиск).
  - Снять с роли — через подтверждение.
  - Организатор должен хоть раз сделать `/start` в боте, чтобы появиться в списке.
- **📌 Кнопки меню** — кастомные URL-кнопки в главном меню игрока:
  - Добавление по схеме «текст → URL» (URL только `http://` / `https://`).
  - Редактирование текста и URL по отдельности, перестановка `⬆️ ⬇️`, удаление с подтверждением.
  - Кнопки появляются у всех игроков после `📨 Обратиться в ДК`, каждая отдельным рядом.

### Для организаторов
- `/admin` — меню организатора (только: рассылка, добавить турнир, управление турнирами, просмотр игроков).
- Организаторы **не** видят кнопок «📨 Получатели обращений» и «👨‍💼 Организаторы» и не могут банить или менять подписки игроков.

## Форматирование сообщений

Бот использует `bot.copy_message`, то есть **копирует то, что прислал админ**, как есть. Markdown / HTML / media — всё сохраняется автоматически, бот ничего не парсит и не валидирует.

**Что поддерживается в рассылке:**
- Жирный, курсив, подчёркнутый, зачёркнутый, моноширинный
- Ссылки, упоминания, code-блоки
- Фото / видео / документ / GIF / голос — **с подписью** (caption) и форматированием в подписи
- Эмодзи

**Что НЕ поддерживается:**
- Альбомы (media group) — несколько фото в одном посте. Каждое фото в альбоме пришлось бы отправлять отдельным сообщением, что разрушает альбом. Если нужно несколько фото — отправь рассылку несколько раз.

Markdown набирается в самом Telegram-клиенте (форматирование через выделение текста → меню форматирования, либо `**жирный**`, `__курсив__` и т.п. в зависимости от клиента). Бот получает уже размеченное сообщение с `entities` и копирует его 1:1.

## Управление контейнером

```bash
docker compose up -d --build      # пересобрать и поднять
docker compose up -d              # поднять без пересборки
docker compose down               # остановить и удалить контейнер
docker compose restart bot        # перезапустить (например после правки .env)
docker compose logs -f bot        # стрим логов
docker compose logs --tail 100 bot  # последние 100 строк
docker compose ps                 # статус
```

Данные сохраняются в `./data/bot.db` — после `down` контейнер удаляется, но БД остаётся.

## Локальная разработка

Без Docker:

```bash
python -m venv .venv
. .venv/bin/activate            # Linux/macOS
# или
.venv\Scripts\activate          # Windows

pip install -e ".[dev]"
python -m bot
```

Требуется Python 3.12+. `.env` должен быть в корне проекта или переменные экспортированы в окружении. `DB_PATH` для локального запуска удобнее изменить на `./data/bot.db`.

## Тесты

```bash
pip install -e ".[dev]"
pytest
```

Тесты используют in-memory SQLite (`:memory:`), не требуют Telegram токена и сети. Покрывают:
- CRUD для турниров и подписок,
- идемпотентность подписки/отписки,
- фильтрацию получателей рассылки (включая исключение заблокировавших бота).

## Архитектура

```
src/bot/
├── __main__.py         # точка входа: загрузка config, инициализация БД и бота, polling
├── config.py           # парсинг и валидация .env
├── db.py               # async SQLite + DDL
├── states.py           # FSM-состояния (AddTournament, EditTournament*, Broadcast)
├── texts.py            # все русскоязычные строки UI и render_card()
├── repositories/       # тонкие обёртки над SQL: users, tournaments, subscriptions
├── handlers/           # роутеры aiogram: common, user, admin, broadcast
├── keyboards/          # inline-клавиатуры и типизированные CallbackData
├── middlewares/
│   ├── deps.py         # инъекция config и репозиториев в хендлеры
│   └── admin_only.py   # фильтр доступа к админ-роутерам
└── services/
    └── broadcast.py    # rate-limited (25 msg/sec) копирование с обработкой 429/403
```

**Стек:**
- Python 3.12, aiogram 3.x, aiosqlite, python-dotenv
- pytest + pytest-asyncio
- Docker (single-stage `python:3.12-slim`)

**Ключевые решения:**
- `bot.copy_message` для рассылки → markdown и медиа сохраняются автоматически.
- Троттлинг 25 msg/sec с обработкой `429 RetryAfter` и `403 Forbidden`.
- Заблокировавшие бота помечаются в БД и исключаются из последующих рассылок.
- FSM-флоу для админских мастеров с превью и подтверждением (защита от случайной массовой отправки).
- Все секреты — через `.env`, в репозитории — только `.env.example`.

Полная спека: [docs/specs/2026-05-15-alm-notification-bot-design.md](docs/specs/2026-05-15-alm-notification-bot-design.md).

## Решение проблем

**Бот не отвечает на `/start`:**
- `docker compose ps` — контейнер `Up`?
- `docker compose logs --tail 100 bot` — есть ошибки?
- Токен верный? Не использован одновременно в другом инстансе бота (Telegram отдаёт `409 Conflict`)?

**Команда `/admin` отвечает «Команда недоступна»:**
- Твой `user_id` есть в `ADMIN_IDS`? Узнай через [@userinfobot](https://t.me/userinfobot).
- После правки `.env` нужен `docker compose restart bot`.

**Рассылка показывает «Получателей: 0»:**
- По «Все» — никто ещё не сделал `/start`.
- По турниру — никто не подписан на этот турнир.

**Часть пользователей не получили рассылку (счётчик «Заблокировали бота»):**
- Они заблокировали бота или удалили чат. Это нормально, бот пометил их `is_blocked=1` и больше не будет беспокоить.

**Сбросить БД (удалить всех пользователей и турниры):**
```bash
docker compose down
rm -rf data/
docker compose up -d
```
